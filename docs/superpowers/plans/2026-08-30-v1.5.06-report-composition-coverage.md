# Research OS v1.5.06 Report Composition Coverage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Preserve the v1.5.05 one-way reporting boundary while ensuring material canonical research artifacts already present in `HumanReadableResearchView` are represented in the final `ResearchReportDocument` body.

**Architecture:** `ResearchReportComposer` remains a deterministic editorial projection only: `ResearchRunResult -> HumanReadableResearchView -> ResearchReportDocument`. The patch adds typed display blocks and section composition for existing view fields; it must not recalculate KPI, funding, thesis, expectation, forecast, valuation, completion, or decision state. Empty source artifacts produce no section.

**Tech Stack:** Python 3.12, Pydantic v2, pytest.

**Spec:** v1.5.05 three-company field acceptance findings on 2026-08-30.

## Global Constraints

- Research OS patch target: `1.5.6`; `CORE_API_VERSION` remains `1.0`.
- No company-specific logic.
- No second Router, Decision Engine, Completion source, Thesis engine, Funding engine, Forecast engine, or Valuation engine.
- Composer consumes only `HumanReadableResearchView`.
- Raw evidence IDs and assumption IDs remain outside the report body and in `AuditAppendix`.
- Existing v1.5.05 sections and semantics remain backward compatible.
- Output sections are omitted when the corresponding canonical artifact is absent.
