# Research OS v1.5.07 Presentation Renderer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a deterministic professional zh-CN Markdown renderer downstream of `ResearchReportDocument` so Research OS can guarantee readable report output without moving semantic or research logic into the publishing layer.

**Architecture:** Introduce `ResearchReportMarkdownRenderer.render(document: ResearchReportDocument) -> str`. The renderer consumes only the typed document produced by `ResearchReportComposer`, selects user-facing fields from typed blocks, emits deterministic Markdown, and places raw provenance only in a clearly separated audit appendix. No research state or numeric value is recalculated.

**Tech Stack:** Python 3.12, Pydantic v2 models already used by Research OS, pytest, plain Markdown generation with no new runtime dependency.

**Spec:** `docs/superpowers/specs/2026-08-30-research-os-v1-5-07-presentation-renderer-design.md`

## Global Constraints

- Target Research OS version: `1.5.7`.
- `CORE_API_VERSION` remains `1.0`.
- `professional-research-view@1.3.0` remains unchanged.
- `research-report-composer@1.1.0` remains unchanged.
- New renderer fingerprint: `professional-markdown-renderer@1.0.0`.
- Renderer input is `ResearchReportDocument` only.
- No company-specific logic.
- No state/KPI/Funding/Thesis/Expectation/Forecast/Valuation recomputation.
- No raw evidence/assumption IDs in the primary body; audit appendix may contain them.
- No new PDF/HTML/browser dependency in v1.5.07.

### Task 2: Implement the deterministic Markdown renderer

**Files:**
- Create: `src/research_os/reporting/markdown_renderer.py`
- Modify: `src/research_os/reporting/__init__.py`
- Test: `tests/unit/reporting/test_markdown_renderer.py`

**Interfaces:**
- Produces: `class ResearchReportMarkdownRenderer` with `version = "professional-markdown-renderer@1.0.0"` and `render(document: ResearchReportDocument) -> str`.

- [ ] **Step 1: Implement renderer dispatch and helpers**

Provide focused private helpers:
- `_semantic_label(value)` — select label/explanation without exposing raw code as primary prose;
- `_display_scalar(value)` — deterministic display of already-provided scalar values, omitting `None`;
- `_render_snapshot(snapshot)`;
- one renderer per typed block;
- `_render_audit_appendix(appendix)`.

Use explicit `isinstance` dispatch over the existing typed block classes. Unsupported block types raise `TypeError` rather than falling back to repr/JSON dumping.

- [ ] **Step 2: Implement body field-selection rules**

FinancialOperating KPI rows use `formatted_value`, `period_label`, semantic status label, and concise explanation. Capital/Funding, Thesis, Expectation/Forecast, Valuation, Monitoring, State Provenance, gaps, limitations, and evidence notes use only the fields allowed by the design spec. Empty values/sections are omitted.

- [ ] **Step 3: Implement audit appendix boundary**

Emit `## 审计附录` after all primary sections. Include repository/commit/version/plugin/module/evidence/assumption metadata deterministically. Raw IDs are permitted only here.

- [ ] **Step 4: Guarantee deterministic output**

Preserve document order for sections/lists, sort only dictionary keys whose ordering is not semantically meaningful, strip trailing spaces, collapse excessive blank lines, and end with exactly one newline.

- [ ] **Step 5: Run renderer tests until GREEN**

Run: `pytest -q tests/unit/reporting/test_markdown_renderer.py`
Expected: all PASS.

- [ ] **Step 6: Run all reporting tests**

Run: `pytest -q tests/unit/reporting`
Expected: all PASS.
