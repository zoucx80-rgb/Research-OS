# Research OS v1.5.10 Migration

Research OS v1.5.10 is a PATCH release for **Professional Research Completeness & Continuous Validation**. It extends the canonical research runtime with typed, PIT-safe completeness artifacts while preserving the existing research semantics and the strict one-way presentation boundary.

## Version fingerprints

- Research OS: `1.5.10`
- Core API: `1.0`
- Research completeness module: `research_completeness@1.0.0`
- Research view: `professional-research-view@1.5.0`
- Report composer: `research-report-composer@1.3.0`
- Markdown renderer: `professional-markdown-renderer@1.2.0`
- HTML renderer: `professional-html-renderer@1.0.0`
- PDF adapter: `professional-pdf-adapter@1.0.0`

## Canonical direction remains unchanged

```text
ResearchContext + ResearchInputs
  -> ResearchRuntime
  -> ResearchRunResult
  -> ResearchViewPresenter
  -> HumanReadableResearchView
  -> ResearchReportComposer
  -> ResearchReportDocument
  -> ResearchReportMarkdownRenderer
  -> MarkdownPresentationArtifact
  -> HtmlPresentationArtifact
  -> PdfPresentationArtifact
```

The new completeness module runs upstream in the canonical runtime. Presenter, Composer, Markdown, HTML and PDF layers only project, arrange and render canonical artifacts; they **不重新计算** research state, completion, valuation, expectation, thesis, peer conclusions, consensus statistics, sensitivity results, monitoring state, or prior-run scoring.

## Additive typed inputs and artifacts

v1.5.10 adds optional typed inputs for:

- operating observations;
- financial time series;
- cash-flow quality inputs;
- consensus observations;
- peer comparables;
- sensitivity cases;
- monitoring rules;
- verification calendar events;
- prior-run review items.

The `research_completeness@1.0.0` runtime module emits canonical artifacts only when the corresponding explicit inputs are available. Missing information remains missing; it is never filled by renderer inference or narrative confidence.

## Research Completeness Gate

Field acceptance evaluates nine independent dimensions:

1. `time_series`
2. `operating_evidence`
3. `cash_flow`
4. `consensus`
5. `peers`
6. `sensitivity`
7. `monitoring_events`
8. `prior_run_validation`
9. `methodology`

Each dimension is exactly one of:

- `PASS` — the declared evidence/artifact requirement is present;
- `INCOMPLETE` — a required dimension lacks sufficient canonical support;
- `NOT_APPLICABLE` — the case explicitly declares the dimension inapplicable.

Required `INCOMPLETE` dimensions fail closed. Explicit `NOT_APPLICABLE` is not a failure and must not cause synthetic data, synthetic report sections, or fabricated conclusions to be created.

## Methodology discipline

- PIT remains `publish_ts <= decision_ts`.
- Consensus dispersion is represented only from explicit source observations; one source is not presented as multi-source consensus.
- Peer comparisons retain period, scope, accounting-definition and business-model interpretation fields rather than silently normalizing incompatible data.
- Sensitivity cases carry explicit shocks and assumption lineage; no hidden universal shock is introduced.
- Prior-run hit/miss evaluation requires an explicit tolerance. There is no hidden universal accuracy threshold.
- The cash-flow bridge may expose `simplified FCF = operating cash flow - capex cash` only when both operands are explicitly available. It is explicitly **not FCFF** and does not infer a working-capital contribution when that decomposition was not supplied.

## Presentation and historical replay

v1.5.10 adds deterministic report sections for financial trends, operating evidence, cash-flow quality, peer comparison, consensus distribution, sensitivities, monitoring/calendar, prior-run review and methodology disclosure. These sections are presentation projections of canonical artifacts only.

The v1.5.09 historical field-acceptance runner remains explicitly pinned to the v1.5.09 Presenter/Composer/Markdown fingerprints, so future top-level reporting upgrades do not mutate historical replay semantics.

## Compatibility boundaries

- **无数据库迁移**：Alembic revisions remain `0001`–`0003`.
- Core API remains `1.0`.
- Existing `ResearchInputs` fields remain compatible; v1.5.10 inputs are additive and optional.
- No new Decision engine, Completion engine, valuation engine, or alternate report semantic path is introduced.
- No **Hospitality Plugin** is added. Hospitality-specific RevPAR/ADR/OCC/same-store/maturity or lease-adjusted economics remain capability-limited unless a future compatible strategy plugin supplies them.
- The three field-validation companies remain fixtures/acceptance evidence only; production `src/research_os` contains no company-specific branches.
