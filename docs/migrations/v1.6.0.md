# Research OS 1.6.0 迁移说明

## 版本边界

```text
Research OS        1.5.12 -> 1.6.0
Core API           1.0    -> 2.0
Plugin API         1.0    -> 2.0
Snapshot Schema    implicit/v1 -> 2.0
HTTP API           prototype -> v1
```

这是一次 clean-break 升级通知。现有 Python 调用、插件、Snapshot 写入方和 HTTP 客户端必须重建；当前包不提供自动转换、v1 parser/reader、adapter 或第二个 Runtime。

## 评审修订的不可变边界

- `behavior_baseline_sha=72ab06c619678b35c31cf7edef7547849e803d16` 是理解已知缺陷和历史 replay 的参考证据，不是当前 v2 兼容门禁；`delivery_parent_sha` 是实际最新 main 父提交，必须在最终交付前重新核验并在发布证据中记录精确 SHA。
- 新运行先构造绑定 `company_id + decision_ts` 的 `FactView`。事实引用为 `EvidenceRef(evidence_id, revision, content_fingerprint)`；旧 ID-only `get` 不迁入运行边界。
- KPI Provider 统一使用 `calculate(facts, definitions, policy) -> tuple[MetricResult, ...]`，M1 冻结最小 `FactView`、`ReportingPeriod`、`AccountingScope`、`MetricResult`、`PolicySnapshot` 和 Registry Port。
- Completion 在 Engine 末端先于 Readiness；Finalizer 只投影，合法不完整结果为 `INCOMPLETE + NOT_READY`。
- Snapshot 分离研究语义指纹与完整性指纹，Descriptor 在持久化后组装；未知 Schema/类型和动态 import 均拒绝。

## Python 调用迁移

旧入口：

```python
runtime = ResearchRuntimeFactory.with_providers(provider)
result = runtime.run_context(context, ResearchInputs(...))
metrics = result.artifacts["kpi.metrics"]
```

新入口：

```python
application = ResearchApplication.build(plugin_providers=(provider,))
result = application.run(
    ResearchRunCommand(
        context=context,
        financial=FinancialResearchInput(...),
        valuation=ValuationResearchInput(...),
    )
)
metrics = result.artifacts.require(KPI_METRICS)
```

没有包内输入转换。调用方必须按上述结构重新生成 `ResearchRunCommand`；旧输入仅能作为集成方自己的重建参考，不能传入当前运行。

## 插件迁移

Plugin API 1.0 的 `modules()` 不再是正式扩展点。Plugin API 2.0 插件返回类型化领域服务；行业适用性与方法支持判断通过 `ApplicabilityResult.evidence_refs` 和 `SupportAssessment.evidence_refs` 返回 revision-bound lineage，选中结果不得降级为裸 Evidence ID：

```python
class MyIndustryPlugin:
    manifest = PluginManifest(..., plugin_api_version="2.0")

    def applicability(self, context, business_model): ...
    def services(self) -> PluginServices: ...
```

旧插件不能由当前运行加载。维护者必须重写、重新打包并发布 API 2.0 插件；当前包不承诺旧插件的错误代码或解析行为。

## Artifact 迁移

字符串读取：

```python
result.artifacts["valuation.reconciliation"]
```

改为：

```python
result.artifacts.require(VALUATION_RECONCILIATION)
```

Artifact Key 同时约束 ID、Schema Version 和 Value Type。

## Snapshot 迁移

- 新写入统一使用 Snapshot Schema 2.0；
- 旧 Snapshot 不能由当前包读取、转换、重新计算或覆盖 hash；
- 需要新格式时，必须以重新生成的 v2 输入创建新的 1.6.0 research run 和 Snapshot；
- 历史 Snapshot 的复现只通过绑定其不可变提交的 isolated executor 完成。

## Completion 迁移

旧：

```text
result.completion
research_completeness artifact
```

新：

```text
result.execution_completion
result.research_readiness
```

两者含义不同，不得互相替代。

## HTTP API 迁移

旧原型路由由 `/api/v1/...` 取代。客户端必须处理 `application/problem+json`、分页 cursor、Snapshot ID 和显式 PIT 参数。

## 数据库迁移

执行：

```bash
alembic upgrade head
```

迁移新增 `research_run`、`artifact_index` 和 PIT 查询索引，在现有 `research_snapshot` 表上增加 Schema 2.0 envelope 字段，并补齐 Evidence 的 `comparison_basis`、`metric_kind` 及 v1.5.12 语义字段映射。旧 Snapshot 行原样保留且 Schema 2.0 字段为 `NULL`，当前 reader 不会把它们当作 v2 Snapshot。新增列从真实 1.5.12 schema 升级；旧行缺失值保持 `NULL/UNKNOWN`，禁止推断、重写事实值或历史 hash。重启后的完整往返必须保留期间、范围、单位、revision、UTC 时间和 raw/normalized 值；downgrade 只删除 1.6.0 新表、索引和列，并保留所有旧字段原值。

完整 Evidence 映射：

```text
company_id, evidence_id, revision, publish_ts,
period, accounting_scope, unit, raw_value, normalized_value,
comparison_basis, metric_kind, source_locator, lineage, content_hash
```

## 历史重放

1.5.08–1.5.12 使用各自 release commit 执行，不依赖 1.6.0 当前源码。Executor 显式隔离解释器、依赖和导入路径，清理或绑定 `GITHUB_SHA`，并断言 `research_os.__file__`、产品/API 版本和实际 Git HEAD 与 Profile 一致；异常也清理 worktree。没有依赖锁时只声明记录环境中的源码复放。历史重放结果不等于 1.6.0 重新研究结果。

## Forecast 与估值术语

Forecast 记录 `train_cutoff`、每个 fold 的 feature availability、label maturity 和 `evaluation_ts`；realized outcome 只能用于成熟后的历史评估。估值状态统一为 `SUPPORTED`、`CONDITIONALLY_SUPPORTED`、`SANITY_CHECK_ONLY`、`CONTRAINDICATED`、`INSUFFICIENT_EVIDENCE`，并保留 `forecast_methods` 服务字段；`ModuleContribution` 未定义前不作为 Plugin API 2.0 能力。
