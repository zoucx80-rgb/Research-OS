# Research OS v1.5.01 Migration Guide

Display version: `v1.5.01`  
Code SemVer: `1.5.1`  
Core API: `1.0` (unchanged)

## Summary

v1.5.01 is a semantic-correctness patch derived from the v1.4.0 real-company field test. It does not replace the canonical runtime, completion gate, decision engine, snapshot service, or plugin architecture.

The release hardens three boundaries:

1. business-model routing uses explicit period semantics for the period-sensitive `inventory_to_revenue` feature;
2. business-model taxonomy/evidence gaps are distinguished from missing industry strategy plugins;
3. canonical machine states can be projected into readable zh-CN research language through `DecisionSummaryPresenter`.

## Router migration

`BusinessModelProfile` adds two backward-compatible fields with defaults:

- `classification_status`
- `classification_reason`

The supported status values are `classified`, `unsupported_taxonomy`, and `insufficient_evidence`.

`BusinessModelRouter` is now `router@1.1.0`. The inventory-to-revenue classification feature contributes only when its Evidence period is explicitly annual. Unknown or interim period semantics do not silently act as annual evidence.

The standard taxonomy adds `hospitality`. This only makes the business model representable; it does not imply specialized hotel KPI coverage.

## CoverageGap migration

`CoverageGap` adds two gap types:

- `business_model_taxonomy`
- `business_model_evidence`

It also adds optional metadata:

- `reason_code`
- `affected_capabilities`
- `fallback_available`

All new fields have defaults. Existing CoverageGap and ExtensionRequest construction remains valid.

A represented model without a compatible industry plugin still produces `industry_strategy`. For example, a hospitality company can now be classified as hospitality while honestly recording that no hospitality industry strategy plugin is installed.

## Human-readable reporting

`DecisionSummary` remains the canonical reporting read model and continues to be built only from `ResearchRunResult`.

Use the new presenter for human-facing zh-CN output:

```python
from research_os.reporting import DecisionSummaryPresenter

view = DecisionSummaryPresenter().build(result, locale="zh-CN")
```

The presenter returns semantic values with three layers:

- `code`: canonical machine state retained as technical metadata;
- `label`: readable zh-CN label;
- `explanation`: readable zh-CN explanation.

For example, a canonical `INSUFFICIENT_EVIDENCE` module state is presented primarily as `证据不足`, while the original machine code remains available as metadata.

Unknown internal reason codes are not printed as the primary research conclusion. They receive a readable fallback explanation while retaining the raw code as technical metadata.

Unsupported locales fail explicitly rather than falling back to raw machine output.

## Completion and decision semantics

`ResearchCompletionGate` remains the sole authority for `COMPLETE` / `INCOMPLETE`.

`DecisionSummaryPresenter` does not calculate or alter:

- completion status;
- decision state;
- thesis state;
- fundamental state;
- expectation state;
- valuation state.

Its `build()` method first invokes the canonical `DecisionSummaryBuilder` and then performs a one-way presentation transformation.

No second completion source or decision source is introduced.

## Snapshot/version semantics

No snapshot schema migration is required. The existing `VersionBundle.report_version` records `semantic-report@1.0.0`, so the human-presentation semantics used for a run are auditable without introducing another result or fingerprint system.

No Alembic/database migration is required.

## Explicit non-goals

v1.5.01 does not add:

- a hospitality/hotel industry strategy plugin;
- RevPAR, ADR, OCC, same-store or hotel unit-economics modules;
- aerospace/high-end-manufacturing-specific KPI logic;
- a Distributor/Funding Loop rewrite;
- a second `ResearchRunResult`;
- a second completion gate;
- company-specific logic for any field-test company.

Those industry-depth extensions remain candidates for later v1.5.x patch releases.
