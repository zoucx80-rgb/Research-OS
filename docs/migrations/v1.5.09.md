# Research OS v1.5.09 Migration

Research OS v1.5.09 is a PATCH release focused on professional research depth and field acceptance. It does not introduce a second research engine and it does not change `CORE_API_VERSION = "1.0"`.

## What changes

The canonical runtime now exposes a read-only `FinancialFactSnapshot` for material filed financial facts already present in the PIT-safe run. Complete human-facing output uses `professional-research-view@1.4.0`, `research-report-composer@1.2.0`, and `professional-markdown-renderer@1.1.0`.

The strict one-way boundary remains:

```text
ResearchRunResult
  -> HumanReadableResearchView
  -> ResearchReportDocument
  -> MarkdownPresentationArtifact
  -> HtmlPresentationArtifact
  -> PdfPresentationArtifact
```

`FinancialFactSnapshot`, the Presenter, Composer, Markdown renderer, HTML renderer, PDF adapter, and field-acceptance tooling are downstream projections or presentation layers. They must **不重新计算** canonical KPI, Funding Loop, Driver/Thesis, Expectation Gap, Forecast, Valuation, Decision State, Completion State, or monitoring semantics.

## Dual field-acceptance status

v1.5.09 separates two independent outcomes:

- `presentation` — HTML/PDF generation, pagination, glyph/layout and typed artifact integrity;
- `research_depth` — required professional research content, canonical financial facts, business-model-specific causal coverage, missingness discipline and non-fabrication.

A case can therefore be `presentation=PASS` and `research_depth=FAIL`. Batch field acceptance is fail-closed: `overall_status=PASS` only when both are PASS.

Permanent three-archetype regressions cover Manufacturing, Distributor, and lease-heavy Hospitality/no-plugin cases. These fixtures are acceptance evidence only; production Core contains no company-specific branches.

## Compatibility

Historical v1.5.08 presentation artifacts and fingerprints remain replayable. HTML and PDF fingerprints remain `professional-html-renderer@1.0.0` and `professional-pdf-adapter@1.0.0`. Existing machine integrations can continue consuming canonical `ResearchRunResult`.

## Database and plugin scope

**无数据库迁移**。No Alembic revision is added; `0003_v1_2_evidence_lineage.py` remains the latest schema migration.

v1.5.09 does not add a **Hospitality Plugin**. Hospitality remains a recognized business-model taxonomy with explicit `industry_strategy` capability gaps when no compatible strategy plugin exists. The release also does not add lease-adjusted ROIC/valuation, a second Completion Gate, a second Decision Engine, automatic trading, or company-specific Core logic.
