# Research OS v1.5.05 Migration Guide

Research OS v1.5.05 is a PATCH release focused on professional reporting composition. `CORE_API_VERSION` remains `1.0`; no database or Alembic migration is required.

## Canonical one-way reporting path

The supported full-report path is now explicitly:

```text
ResearchRunResult
    ↓
ResearchViewPresenter
    ↓
HumanReadableResearchView
    ↓
ResearchReportComposer
    ↓
ResearchReportDocument
    ↓
renderer / PDF
```

`ResearchReportComposer` is an editorial projection only. It must not recalculate or override Decision State, Completion, Thesis, Funding Loop, Forecast, valuation routing, expectation state, or business-model classification. It rejects raw dictionaries as an alternate semantic input path.

## Human-readable research view

The complete presenter fingerprint is now `professional-research-view@1.3.0`.

The view adds read-only projections for:

- structured expectation-gap results when explicit market and Research OS views exist;
- structured valuation outputs, ranges, scenarios and lineage when explicitly supplied;
- canonical monitoring information from the next verification event and existing falsifiers;
- lease-heavy presentation limitations without implying that lease-adjusted ROIC or valuation has been implemented.

Missing market consensus remains missing and does not produce a fabricated expectation gap. Valuation upside/downside is not derived by presentation merely because a current price and a value estimate are present.

## ResearchReportComposer

`research-report-composer@1.0.0` adds deterministic report composition over `HumanReadableResearchView`:

- first-page decision snapshot copies canonical states;
- material risks are deduplicated by canonical semantic code;
- causal bridges use an existing valuation `driver_bridge` or existing Driver Graph edges only;
- unsupported edges are never invented for narrative smoothness;
- raw evidence and assumption IDs live in the audit appendix by default;
- the main body uses a concise evidence-traceability note instead of a provenance dump;
- unresolved items are separated into evidence missing, capability missing, not applicable, and presentation/deferred limitations;
- empty sections are omitted;
- repository SHA, plugin identities, module statuses and raw provenance remain audit metadata rather than primary investment prose.

## Display-only number formatting

Human-readable CNY formatting may scale large display values to `万元` / `亿元`, but machine values are unchanged. Display formatting is not a calculation input.

## Lease-heavy hospitality and other uncovered industries

v1.5.05 still does **not** add a Hospitality Plugin or a lease-adjusted valuation framework. A recognized hospitality company without a compatible industry strategy plugin remains coverage-limited. Lease-heavy economics must be shown as a research limitation rather than converted into unsupported claims such as “light asset” or “low capital intensity”.

## Compatibility

Existing machine integrations may continue consuming `ResearchRunResult`, `DecisionSummary`, and prior compatible presentation surfaces. Consumers that want the complete v1.5.05 professional report should use:

```text
ResearchRunResult → HumanReadableResearchView → ResearchReportComposer → ResearchReportDocument
```

Historical snapshots retain their recorded presenter/component fingerprints. v1.5.05 introduces no company-specific Core logic, no second Decision Engine, no second Completion Gate, no new automatic trading behavior, and no database migration.
