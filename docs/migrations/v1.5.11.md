# Research OS v1.5.11 Migration

Research OS v1.5.11 is a semantic-correctness PATCH release. Core API remains `1.0` and there is **无数据库迁移**.

## What changes

- Active thesis analysis now emits typed directional signals and explicit comparison-basis assessments.
- Cross-metric growth conclusions fail closed as `NOT_COMPARABLE` unless comparison basis and economic metric kind are compatible.
- Mixed current evidence without an explicit prior directional thesis is `UNRESOLVED` / waiting for confirmation rather than automatically `WEAKENING`.
- Missing auditable PIT market-expectation evidence is `UNKNOWN`, not `MIXED`.
- `professional-research-view@1.6.0` projects the canonical typed signal artifact, deduplicates only semantically equivalent display aliases, and does not create a second analytical path.
- `professional-markdown-renderer@1.3.0` suppresses literal null leakage, uses investor-facing date formatting, labels admitted-evidence quality narrowly, and displays valuation-model suitability categorically rather than as fake precision.

## Release-governance migration

v1.5.11 also removes patch-version orchestration duplication without changing research semantics:

- package metadata now reads its dynamic version from the import-free `research_os.version` identity leaf;
- `research_os.release.manifest.CURRENT_RELEASE` is the release descriptor for component fingerprints, enabled verification packs, and selected field replay profiles;
- release checks are composed through the verification registry rather than a new `runtime_vX_Y_Z.py` for each patch;
- GitHub Actions calls the stable `scripts/verify_release_pipeline.py` entry point instead of embedding one CI block per historical patch;
- published v1.5.08-v1.5.10 field acceptance remains frozen behind explicit replay profiles;
- current field acceptance uses the non-versioned `research_os.acceptance` core, while the v1.5.11 runner contains only v1.5.11-specific semantic acceptance rules.

For a future ordinary patch release, extend capability code/tests plus the manifest/registries and release documentation. Do not copy the stable release runtime, historical runners, or CI topology.

## One-way boundary

The pipeline remains strictly one-way:

`ResearchContext + ResearchInputs -> canonical runtime artifacts -> ResearchRunResult -> HumanReadableResearchView -> ResearchReportDocument -> Markdown -> HTML -> PDF`

Reporting and presentation **不重新计算** thesis, expectation, comparison, completion, decision or valuation semantics. Exact machine metadata remains auditable downstream.

## Compatibility

Historical v1.5.05-v1.5.10 presenter/renderer implementations remain available for replay. The legacy thesis-signal artifact is retained for historical compatibility while the active v1.5.11 view consumes `thesis.semantic_signal_assessment` as the canonical typed signal source.

No company/security-specific production rule, Hospitality Plugin, automatic trading rule, new Completion Gate, or new Decision Engine is introduced.
