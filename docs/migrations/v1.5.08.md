# Research OS v1.5.08 Migration

Research OS v1.5.08 adds the professional HTML/PDF presentation pipeline downstream of the v1.5.07 Markdown renderer. It is a presentation release; no research engine, state authority, or database schema changes.

## Canonical direction

```text
ResearchRunResult
    -> HumanReadableResearchView
    -> ResearchReportDocument
    -> MarkdownPresentationArtifact
    -> HtmlPresentationArtifact
    -> PdfPresentationArtifact
```

The concrete components are `ResearchViewPresenter`, `ResearchReportComposer`, `MarkdownArtifactRenderer` (which delegates to the unchanged `ResearchReportMarkdownRenderer`), `ProfessionalHtmlRenderer`, and `PlaywrightPdfAdapter`.

Every artifact is immutable and records `renderer_version`, `source_hash`, and `content_hash`. Markdown hashes the canonical `ResearchReportDocument`; every later `source_hash` equals the immediately preceding artifact's `content_hash`. HTML additionally records and validates the exact embedded print-CSS hash, and PDF records the Playwright/Chromium backend version. Artifact copies are revalidated so a content update cannot retain a stale hash.

HTML metadata carries renderer, upstream source, and style hashes. The HTML content hash remains in the typed artifact and acceptance manifest because embedding a file's own hash inside that file would be self-referential.

There is no direct `ResearchRunResult -> PDF` or `HumanReadableResearchView -> PDF` path.

## Install the optional PDF backend

Core/default installations do not include a browser:

```bash
python -m pip install -e ".[pdf]"
python -m playwright install chromium
```

CI may use `python -m playwright install --with-deps chromium`.

Playwright is imported only inside `PlaywrightPdfAdapter.render()`. `ResearchRuntime`, reporting composition, plugins, KPI, Funding Loop, Thesis, Expectation, Forecast, Valuation, Decision, and Completion do not depend on Playwright or the PDF adapter.

## Presentation behavior

`ProfessionalHtmlRenderer` consumes `MarkdownPresentationArtifact` only. It emits self-contained UTF-8 HTML with:

- first-page Investment Decision Snapshot;
- financial/KPI and Capital Efficiency/Funding Loop sections;
- Driver causal bridge and Thesis/Anti-Thesis/Falsifiers;
- Expectation/Forecast and Valuation sections;
- Monitoring, Research Gaps, and a page-separated Audit Appendix;
- embedded A4 CSS for repeating table headers, page breaks, long text, Chinese font fallbacks, and black-and-white readability.

`PlaywrightPdfAdapter` consumes `HtmlPresentationArtifact` only and prints that HTML with page numbering. It rejects active/external markup, disables JavaScript and service workers, and blocks network requests. It does **不重新计算** KPI, Funding Loop, Driver/Thesis, Expectation Gap, Forecast, Valuation, Decision State, or Completion State.

Raw Python repr, internal fields, plugin IDs, raw evidence IDs, and raw assumption IDs remain after the Audit Appendix boundary. Missing values remain missing. Factoring remains **Factoring** and is not reinterpreted as Debt by HTML/PDF presentation.

## Compatibility

- Research OS: `1.5.8`
- Core API: `1.0`
- Presenter: `professional-research-view@1.3.0` unchanged
- Composer: `research-report-composer@1.1.0` unchanged
- Markdown renderer: `professional-markdown-renderer@1.0.0` unchanged
- HTML renderer: `professional-html-renderer@1.0.0`
- PDF adapter: `professional-pdf-adapter@1.0.0`

Existing machine and Markdown consumers need not install Playwright. No database or Alembic migration is required.
