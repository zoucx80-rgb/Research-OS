# Research OS v1.5.02 Migration Guide

Research OS v1.5.02 (code SemVer `1.5.2`) is a backward-compatible semantic-integrity release. `CORE_API_VERSION` remains `1.0` and no database or Alembic migration is required.

## What changes

### Human-facing research output

`DecisionSummaryPresenter` remains available for decision-summary-only callers. Complete human-facing stock research should now use `ResearchViewPresenter`, which projects one canonical `ResearchRunResult` into a human-readable zh-CN research view covering business-model classification, plugin selection, Coverage Gaps, KPI metrics, Funding Loop, Driver Graph, Thesis, expectation quality, valuation routing, and the existing decision/completion summary.

```python
from research_os.reporting import ResearchViewPresenter

view = ResearchViewPresenter().build(result, locale="zh-CN")
```

The direction remains one-way:

```text
ResearchRunResult -> ResearchViewPresenter -> HumanReadableResearchView
```

Presentation cannot promote or demote completion, decision, thesis, valuation, expectation, or any other canonical machine state. `ResearchCompletionGate` remains the only authority for `COMPLETE` / `INCOMPLETE`.

### Coverage-aware narrative

If the routed primary business model lacks a compatible industry strategy plugin, generic Driver Graph information may still be produced for continuity, but it is explicitly marked coverage-limited. The runtime does not produce an active Thesis or Claim that could be mistaken for specialized industry research, and the corresponding module remains `INSUFFICIENT_EVIDENCE`.

This is especially important for represented business models such as `hospitality` when a specialized Hospitality plugin has not yet been installed.

### Primary industry isolation

Canonical KPI / Driver / Thesis execution now follows the primary business model only. Secondary business models remain classification and coverage metadata. An unsupported secondary model still produces a Coverage Gap, but a compatible secondary plugin is not automatically co-executed in the primary KPI chain.

This prevents cross-pack contamination while preserving visibility into mixed-business companies.

### Business-model status truthfulness

`BusinessModelModule` now reports `PASS` only when the Router returns `classification_status=classified`. Unsupported taxonomy and insufficient classification evidence remain available as structured `BusinessModelProfile` artifacts but correctly produce `INSUFFICIENT_EVIDENCE` at the module layer.

### Funding Loop material risk

The existing `DecisionContext.material_risk` field is now populated from canonical Funding Loop evidence when:

- `funding_state=stressed`; or
- `funding_state=debt_funded` with both `DEBT_FUNDS_NWC` and `NEGATIVE_OCF`.

No new decision state is introduced. Severe financing-risk cases can therefore enter the existing `RISK_REVIEW` state rather than being understated as ordinary monitoring.

### Expectation quality

No new consensus schema is introduced. v1.5.02 uses the existing `ConsensusVintage.source_count` and `source_quality` plus vintage age to provide a non-directional quality assessment:

- fewer than 3 sources -> thin consensus;
- source quality below 0.5 -> low source quality;
- vintage older than 90 days -> stale consensus.

This quality context does not invent a market-expectation direction and does not replace expectation-evidence PIT validation.

### Industry report contributions

Built-in Manufacturing and Distributor plugins now provide structured report contributions with titles, descriptions, research questions and artifact references. Existing plugins remain compatible because the new `ReportContribution` fields have defaults.

## Versioned presentation

The default snapshot/report version becomes:

`semantic-research-view@1.0.0`

The previous `semantic-report@1.0.0` decision-summary presenter remains available for compatibility. Historical snapshots retain their original report versions.

## Compatibility

Existing serialized `BusinessModelProfile`, `CoverageGap`, `DriverGraphResult`, `ReportContribution`, `ResearchInputs`, `ResearchRunResult`, and snapshots remain loadable because new model fields use backward-compatible defaults.

No public decision state is removed or renamed. No second ResearchRunResult, Completion Gate, Decision Engine, or Snapshot service is introduced.

## Explicitly not included

v1.5.02 does not add a Hospitality Industry Plugin, production RevPAR/ADR/OCC calculations, aerospace-company-specific Core logic, automatic balance-sheet restatement for derecognized factoring, or a wholesale rewrite of Funding Loop thresholds.
