# Research OS v1.1 → v1.2 Migration

Research OS v1.2 is an additive safety and methodology release. It does not rewrite historical Research Snapshots or mutate the historical `v1.1.0` release tag.

## Database migration

Alembic revision `0003_v1_2_evidence_lineage` extends the existing `evidence` table with persistent lineage fields:

| v1.1 column/state | v1.2 destination | Reversible |
|---|---|---|
| `value_json` | retained unchanged | yes |
| in-memory `raw_value` only | `raw_value_json` | yes* |
| in-memory `normalized_value` only | `normalized_value_json` | yes* |
| in-memory `period` only | `period` | yes* |
| in-memory `version` only | `version` | yes* |

`*` Downgrading to `0002_v1_1_semantics` drops the four v1.2-only columns. Existing v1.1 columns remain intact, but data stored exclusively in the new lineage columns is intentionally removed by the downgrade. Export that metadata first if a production rollback must preserve it outside the database.

The migration is tested through `upgrade head → downgrade 0002_v1_1_semantics → upgrade head`.

## Domain compatibility

`Evidence.value` remains available for backward compatibility. v1.2 additionally preserves raw/normalized representations and explicit period/version metadata so material values can be reconstructed and audited after storage round trips.

Existing callers may continue using v1.1-style domain inputs. New v1.2 research runs should populate the richer lineage fields whenever the source supports them.

## Research completion behavior

v1.2 introduces machine-enforced safety gates. This changes completion semantics, not the meaning of historical snapshots:

- a successful tool/process run is not automatically a complete research run;
- hard financial/preflight/valuation/decision failures block completion;
- unsupported expectation evidence remains `INSUFFICIENT_EVIDENCE` rather than being inferred;
- `FINAL_STATUS` is only `COMPLETE` or `INCOMPLETE`;
- a completed report cannot contain an illegal decision state or unsupported expectation/valuation conclusion.

Callers that do not provide the v1.2 safety context retain compatible orchestration behavior, but their output must not be silently represented as a v1.2-complete research result.

## Operational upgrade

```bash
python -m pip install -e .
DATABASE_URL=sqlite:///research_os.db alembic -c alembic.ini upgrade head
pytest -q tests/integration/storage/test_v1_2_lineage_migration.py
pytest -q
python scripts/release_gate_v1_1.py
```

The release-gate script keeps its historical filename for compatibility and reads the current package version dynamically.

## Rollback

```bash
DATABASE_URL=sqlite:///research_os.db alembic -c alembic.ini downgrade 0002_v1_1_semantics
```

Rollback does not alter historical Research Snapshot payloads or release tags. Re-upgrading to `head` recreates the lineage columns.
