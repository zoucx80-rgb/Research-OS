# Research OS v1.5.07 Migration

Research OS v1.5.07 is a reporting-presentation PATCH. It adds a deterministic Markdown renderer downstream of the existing canonical research and composition pipeline.

## Canonical direction

```text
ResearchRunResult
    ↓
ResearchViewPresenter
    ↓
HumanReadableResearchView
    ↓
ResearchReportComposer
    ↓
ResearchReportDocument
    ↓
ResearchReportMarkdownRenderer
    ↓
Markdown
```

The renderer accepts `ResearchReportDocument` only. It does **not** accept `ResearchRunResult`, `HumanReadableResearchView`, arbitrary dictionaries, or raw machine artifacts as an alternate semantic path.

## What changes

- Adds public `ResearchReportMarkdownRenderer`.
- Adds renderer fingerprint `professional-markdown-renderer@1.0.0`.
- Renders a deterministic zh-CN investment-research Markdown document with an investment-decision snapshot, typed report sections, monitoring, research gaps, limitations, and a separate audit appendix.
- Keeps repository SHA, module/plugin metadata, raw evidence IDs, and raw assumption IDs in the audit appendix rather than primary investment prose.
- Adds permanent Manufacturing, Distributor, and lease-heavy Hospitality/no-plugin rendering regressions.

## What does not change

- `CORE_API_VERSION` remains `1.0`.
- `ResearchCompletionGate` remains the only authority for `COMPLETE` / `INCOMPLETE`.
- `ResearchViewPresenter` remains `professional-research-view@1.3.0`.
- `ResearchReportComposer` remains `research-report-composer@1.1.0`.
- The renderer does **不重新计算** business-model classification, KPI, Financial Sanity, Capital Efficiency, Funding Loop, Driver Graph, Thesis, Expectation Gap, Forecast, valuation, Decision State, Completion State, or monitoring thresholds.
- No Hospitality Plugin, lease-adjusted valuation engine, HTML/CSS renderer, browser engine, or PDF engine is introduced.

## Consumer migration

Existing machine consumers can continue consuming canonical `ResearchRunResult`. Existing composition consumers can continue consuming `ResearchReportDocument`.

Consumers that need a canonical human-readable Markdown artifact should use:

```python
from research_os.reporting import (
    ResearchReportComposer,
    ResearchReportMarkdownRenderer,
    ResearchViewPresenter,
)

view = ResearchViewPresenter().build(result, locale="zh-CN")
document = ResearchReportComposer().compose(view)
markdown = ResearchReportMarkdownRenderer().render(document)
```

Downstream HTML/PDF tooling may consume this Markdown or a future renderer model, but must not feed presentation-derived values back into research semantics.

## Database migration

No database or Alembic migration is required.
