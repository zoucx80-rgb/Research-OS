# Research OS v1.5.06 Migration

Research OS v1.5.06 is a reporting-composition PATCH release. It does not introduce a database or Alembic migration and does not change `CORE_API_VERSION`, which remains `1.0`.

## What changes

The canonical reporting direction remains strictly one-way:

```text
ResearchRunResult
    ↓
ResearchViewPresenter
    ↓
HumanReadableResearchView
    ↓
ResearchReportComposer
    ↓
ResearchReportDocument
    ↓
renderer / PDF
```

`ResearchViewPresenter` remains `professional-research-view@1.3.0`. `ResearchReportComposer` advances to `research-report-composer@1.1.0`.

v1.5.05 already projected material canonical research artifacts into `HumanReadableResearchView`, but the final report body composed only a narrow subset. v1.5.06 expands deterministic body composition to include existing human-readable artifacts when present:

- Financial Sanity and KPI metrics;
- Capital Efficiency and Funding Loop;
- Thesis / Anti-Thesis / Falsifiers and thesis-signal assessment;
- expectation quality and Forecast Discipline;
- valuation model fitness and valuation-execution rationale;
- state provenance.

## Semantic boundary

The Composer remains an editorial projection only. It **不重新计算** KPI, Funding Loop, Thesis, expectation, Forecast, valuation, business-model, Decision, or Completion state. It accepts `HumanReadableResearchView` rather than creating an alternate path from raw machine artifacts.

Empty canonical artifacts remain absent from the body. A coverage-limited Hospitality company without a compatible strategy plugin does not receive fabricated RevPAR, ADR, OCC, same-store, unit-economics, or other hotel-specific outputs merely to fill a report section.

Raw evidence IDs, assumption IDs, repository/plugin/module identities, and valuation lineage identifiers remain audit metadata rather than primary investment prose. The main body carries human-readable values and explanations only.

## Compatibility

Existing consumers of `ResearchRunResult`, `DecisionSummary`, and `HumanReadableResearchView` require no migration. Existing renderer integrations should tolerate the additive typed report blocks in `ResearchReportDocument` and may add styling for them.

No Hospitality Plugin, lease-adjusted valuation engine, Forecast rewrite, second Decision Engine, second Completion Gate, or company-specific Core logic is introduced.
